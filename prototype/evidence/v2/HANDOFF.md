# Petros World V2 — verified implementation

Local running URL: **http://127.0.0.1:3021/prototype**. Verified October 28, 2026 (Asia/Kolkata). This is a local showcase, not a public deployment. This handoff supersedes the earlier World screenshots and recording in `../redesign/`.

## Requested corrections and causes

The five supplied screenshots exposed real ownership failures. The former HUD, floating teaching label, source card, quiz and cloud each chose absolute viewport positions. The sprite projection omitted the renderer canvas’s offset in the viewport. Its fixed upward cloud transform could push a long response behind the title. Board labels were separate textures with no shared text grid. A single short caption and a manual practice button did not conduct the requested demonstration.

V2 reserves separate regions for the header, renderer, companion captions when a dock is needed, temporary responses, and footer controls. The response region measures its actual content through ResizeObserver, rather than permanently covering the scene with an oversized card. World uses its own renderer and paced teaching script; Classic retains its interface.

## Priority 1 — layout, typography, clouds and board

The header is 76px desktop / 72px narrow. It contains Exit, one lesson title/subtitle, and preferences. The footer is 72px / 64px with Pause, Ask, Overview and contextual tools/source access. Secondary stations collapse behind an accessible control during teaching and on smaller viewports. The source-book card appears briefly, then teaching begins automatically. Source access remains a secondary footer action.

Cloud positions are computed from the actual sprite head/feet projection plus the renderer’s DOM offset. Candidate positions lie beside or above the head with a 14px gap. Bounds and protected UI/board/experiment rectangles determine whether a candidate fits. The tail changes side to point back toward Petros. When no safe candidate fits, and on narrow viewports, a reserved companion caption dock carries the message. The cloud hides while the sprite is hidden during an anchor fade. It has a visible close button and bounded short content; long answers use a focused conversation surface.

The board has one content owner: `board-content.ts` draws a dedicated 1600×900 canvas, rendered onto the physical board surface by `board-surface.tsx`. Its named zones are header (12%), explanation (13%), demonstration (65%) and footnote/source (10%). Text is measured and wrapped before drawing; overflow is reported as a layout error, never fixed by shrinking critical text. Nodes/lines stay inside their assigned diagram zone. Pointer hits use the same canvas layout rectangles, mapped from the real mesh UV coordinates. An equivalent semantic text representation follows the same current layout. A temporary readable board view offers large text/node controls on narrow screens.

**Typography correction:** Next.js registers Outfit under an internal self-hosted family name. A literal canvas `Outfit, sans-serif` request silently used fallback sans-serif. V2 resolves the actual inherited family from the showcase route, loads its 400/500/600 weights before creating World textures, and uses that family for the HUD, board and 3D labels. Header, body, controls, captions and values have coordinated weights, line heights and spacing. `typography-results.json` verifies identical Classic/UI/board families, an actually loaded Outfit variable face, different text metrics from generic sans-serif, and no board bounds errors. The internal family hash may change between builds; no hash is hardcoded.

## Priority 2 — Petros conducts the lesson

Every authorized teaching beat specifies an ID, exact statement, station, target, visual operation, duration, interaction gate, source pages and continuation. The timer advances only while teaching is active, the camera has settled, and the lesson is not paused, interrupted, reading, typing or in preferences. It does not derive visual operations from arbitrary model prose. Presentation progress is saved in the root shared state, including script, beat and elapsed time.

After the real source book reaches its stand, the compact source presentation lasts about 2.4 seconds. Teaching then begins without a “Read source” or manual sentence-advance requirement. Pause, replay, skip and interruption are available. The current demonstration is **text-led**, with paced captions. It does not claim spoken TTS.

The AI3 reference script automatically:

1. Introduces the game/opponent problem and MAX/MIN participants.
2. Displays MAX, then MIN, and constructs the three branches incrementally.
3. Reveals A=(3,5), B=(2,9), C=(4,1).
4. Compares each MIN pair and animates its selected numeric value toward the parent.
5. Backs up MAX(3,2,1)=3 and emphasizes the root choice.
6. Opens the branch-choice gate. The real deterministic minimax result supplies the expected answer.
7. Responds to the chosen branch, including an incorrect choice and correction opportunity.
8. Runs the actual left-to-right alpha-beta traversal automatically, with alpha/beta explanations, visited paths and the skipped 9.
9. Pauses for a contextual “Why didn’t you check the 9?” question and resumes the same saved beat.
10. Continues through the remaining prepared checkpoints and recap.

**Ordering matters:** the original Classic example used C=(1,4), giving four examined leaves and two skipped leaves. V2 explicitly requests C=(4,1), giving **five examined leaves and one skipped leaf**, with the same minimax result 3. `tree-variant.ts` keeps that ordering in shared visual state and adapts the affected questions/feedback deterministically. A fresh Classic lesson retains its original example. Switching from a World V2 lesson to Classic retains the V2 ordering and matching questions, so the modes never disagree about the active example. The requested prediction gate uses AI3-Q07 first; the remaining unanswered checkpoints then continue without marking earlier questions complete automatically.

## Priority 3 — enclosed human-scale interior

The old elevated open platform is replaced by an enclosed 9.8m × 7.6m room, approximately 3.2m high. The camera is inside at human eye height (arrival 1.67m, 50° perspective FOV). The room includes a ceiling/coffers and light fixtures, architectural wall depth and trim, a window/daylight area, rug, wood flooring, two tall bookcases, shelf lights, desk/chair/lamp/notebooks/stationery/mug, a reading stand, plants, and a dedicated experiment table with no generic three-sphere prop.

The library has **104 varied instanced decorative books**, four horizontal stack books, four course-source books and two curiosity notebooks (114 total). Dimensions/colors vary; the source books have explicit AI/EHS module spines. Instancing keeps decorative books to two batches. The four source books remain independent meshes so retrieval is a real approximately 900ms 3D animation to the reading stand. The selected source and pages appear in the compact resource presentation.

Materials are original procedural oak/plaster/linen textures with physically based roughness/material response. Daylight, controlled warm local fill, shelf emission and soft shadow mapping create depth. The design is a detailed procedural interior; **it is not claimed photorealistic**. No suitable local licensed GLB/GLTF environment was present, and no unlicensed model was fetched. No image replacement was used for the room.

Four controlled camera views frame arrival, library, board and experiment. Ordinary transitions use smooth easing over 900ms. The board view is near frontal and gives it the dominant teaching area with Petros beside it. Camera fitting accounts for the actual renderer dimensions, including portrait layouts. Reduced motion uses direct changes; typing and precise selections stop camera travel. No free orbit/first-person controls or random spins were added. The renderer is demand-driven and caps DPR at 1.5. The full-browser development run sampled 6 animated camera transitions at 60.4–60.8 FPS (median 60.6); the final scene reported 16,014 triangles and 93 draw calls. These are this Mac’s measurements, not device-wide guarantees (`performance.json`).

## Interruption, state and character

One root `ShowcaseState` owns lesson/source/question/answers/completion/conversation/visual values and the saved World presentation beat. Both renderers use the existing shared controller and evaluator. A question pauses the timer, preserves the visual and highlighted target, and supplies that context to the prepared retrieval. Replies are labelled prepared; a mismatched node asks for clarification. “Continue lesson” resumes the saved checkpoint. A “go back” request can revisit the previous authorized teaching beat without deleting completion. Graphics retry and mode changes preserve answers and drafts. Reload remains memory-only and clears the demo session.

Original Petros art is unchanged. The existing neutral/listening/thinking/pointing PNG poses are camera-facing sprites at grounded station anchors. Anchor changes fade out, relocate while hidden and fade in. There is no sliding locomotion, fabricated grabbing, sitting, blinking, lip sync or articulated gesture. A faithful rig remains a separate approved art requirement.

## Scope and remaining limitations

[Exact added/modified files](files-changed.txt) includes implementation, tests and evidence. All new V2 work stays in root `prototype/`; no new external route, auth, assessment, M4/M5/M6 engine, source PDF or original character asset edits. Existing route/workspace integration is reused. The token-generation step produced no content diff. The pre-existing working tree was preserved (`baseline-status.txt`, `status-scope.json`). No commit, PR, enrollment or deployment was performed.

General live model answers and arbitrary topic generation remain unavailable through this isolated showcase. Existing tutor routes write production academic/conversation state, and the showcase retains its honest HTTP503 boundary rather than disguising retrieval as live reasoning. Prepared contextual responses are bounded to supported visual/source contexts.

The repository also contains an existing gated Voice Preview and unrelated public narration fixtures. Those do not provide an approved, working narration track for these exact World scripts. No production spending/tester gate was bypassed and no unrelated recording was substituted. This delivered demonstration uses paced **text-only captions**, not functioning TTS. A qualified isolated voice/provider adapter or matching approved narration is future work.

The procedural room is more detailed and human-scale, but no photorealistic environment or rigged character is claimed. Voice, unrestricted model reasoning, durable reload recovery, public hosting and broad device certification remain incomplete/unqualified. Small decorative book-spine text is not the primary reading surface; the selected module/source card and readable board view provide accessible text. Safety demonstrations are educational examples, not professional certification.
