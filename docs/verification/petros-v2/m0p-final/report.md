# Petros V2 — M0-P final interaction refinement

Implemented on 11 October 2026. M0-P is complete and paused for visual review. The Edrion shell, typography, colors, source bindings, shared reducer, semantic IDs and fixture-only authority remain in place.

**Playback root cause and fix.** The previous controller finished a beat by setting `progress = 1` and `status = paused`. Calling `play()` then returned early from `startBeat()` for the already acknowledged action, kept the same timeline index, and finished that same beat again. `resume()` was an alias for `play()`, so the separate controls did not represent distinct reliable transitions. The new controller resumes an unfinished reveal and advances a completed beat exactly once. Automatic playback continues through text beats, with a short reading interval, and stops at the student barrier. Manual Next step shows one complete beat and remains paused. The same primary button displays Play, Pause, Continue, Continue lesson, Your turn or Replay from the actual state. Your turn is disabled with an explanation until submission. Completed recovery keeps Replay. Restart clears the local practice copy and fences reveal, progression and source-check callbacks.

A progressive checkpoint cannot open editing before its reveal finishes. Both controller validation and UI permissions enforce that boundary. Accepted student operations and submission receipts remain in the event journal; continuing does not replay an acknowledged operation or replace the student's committed work.

**Ask Petros and selection.** Ask Petros safely interrupts the same timeline, preserves its index and partial reveal, opens the existing conversation panel and focuses its question input. It works from playback, selected diagram nodes and relationships, and selected passage/equation cards. The conversation displays the semantic target and current canvas revision; Clear is available in the conversation and on the canvas. The main node surface, connection path/label, expression and source passage can select a target. Protected surfaces select without starting an edit or drag. Question submission uses Send question, and the primary transport returns to the saved lesson checkpoint. Dialogue remains deterministic fixture text.

Browser testing also exposed a pointer failure caused by changing speech-bubble height on input blur. The reserved companion space now stays stable, preventing the conversation's Clear and Send controls from moving between pointer-down and pointer-up.

**Diagram routing and editing.** The former quadratic curves placed parallel and reverse connections into the same upper corridor. The replacement builds a rectilinear visibility grid from inflated node bounds, ports, exterior corridors, existing paths and label bounds. A shortest-path search penalizes bends, crossings, nearby parallel segments and occupied label areas. Routes use rounded corners, distribute across top/bottom/side corridors, and allocate distinct attachment positions. Labels follow their own path segments and use positions clear of nodes and other paths. Fixed-size arrowheads keep direction readable when selecting a connection. Node movement recalculates geometry without changing the reducer's semantic endpoints, direction, labels or saved coordinates.

Each permitted node exposes four ports. Pointer dragging shows a live arrow preview and highlights a valid destination; dropping on a destination commits the validated relationship. Escape, pointer cancellation and an invalid release cancel it. Touch uses the contextual Connect and Move controls; keyboard uses C, destination focus and Enter/Space. Relationship labels edit in place using the existing supported vocabulary. Duplicate source/target/relation tuples are explained and rejected; different relationships and reverse directions remain valid. Remove, undo and redo use existing revisioned operations. A concurrent undo invalidates an active gesture, and failed rename text stays available for correction.

**Space and framing.** Teaching/Your turn/Editing/Reviewing/Paused is a compact toolbar indicator. The permanent teaching-copy hint and text-help row have been replaced by a tooltip and toolbar disclosure. Source preview starts collapsed. At the verified 1440 × 900 desktop size, usable drawing height increased from 320 to 560 CSS pixels. Content bounds include nodes, complete routes and label rectangles, with a maximum automatic zoom of 1.45. Teaching reframes smoothly as content grows; reduced motion uses immediate framing. Editing retains the student's camera until they request Fit, zoom or pan. Mobile Restart uses a labelled icon to avoid an additional footer row. The conversation and source use one scrolling panel on desktop, and the mobile page uses its existing content scrollport.

The browser checks exercised repeated playback cycles, automatic progression, manual steps, partial interruption, paused and completed reload, replay, restart, main-surface selection, contextual focus, protected teaching content, real node dragging, direct port creation, three parallel relationships, reverse direction, intermediate-node routing, label editing, removal/history recovery, keyboard creation, stale drag after concurrent undo, retained invalid rename, captured-pointer Escape and invalid-drop cancellation, source/equation selection, committed submission, and responsive/touch/reduced-motion behavior. Tested sizes were 1440 × 900, 1440 × 600, 768 × 800, 360 × 800 and 320 × 568. Footer edges and toolbar containment were measured; no horizontal outer-page overflow was observed.

The harness used an isolated Next output directory and a disposable authentication-metadata API. Recorded API traffic was exclusively GET `/v1/student/me`. No real student learning records, production assessment/evidence writes, paid provider calls, database migrations, RLS/role changes or M1–M8 work occurred. The existing signed-in preview and unrelated uncommitted changes were preserved.

**Remaining limitations.** This is still the three-node M0-P learning fixture, with the existing logical coordinate bounds and three supported relationship labels: provides, connects and supports. The routing engine has seven-node regression coverage, but crossing-free routing is not guaranteed for arbitrary dense or nonplanar graphs. Very short phone windows use vertical scrolling; dense diagrams can require zoom/pan or the text alternative. Port-side preferences last for the current editor session; after reload the router assigns ports again while preserving semantic endpoints and direction. Manual bend-point handles and free-form relationship labels are not implemented because the current validated operation contract has no corresponding fields. In-progress gestures and unsaved rename buffers are committed to checkpoints only after a valid operation succeeds. Touch was tested through Chromium emulation; this does not establish device-specific Safari behavior.

Selection, editing, history, routing, playback and checkpoint recovery are implemented. Conversation and feedback remain explicitly simulated local fixtures. Genuine adaptive AI teaching and production learning/evidence integration remain future milestones. Work stops here for visual review.
