## A. Executive summary

Implemented an actual source-pinned, bidirectional teaching loop in the existing M4 session owner. Two separately owned synthetic Cloud students commit different work, receive real criterion evaluation, get different instructional actions, edit the resulting canvas, commit corrections and receive private evaluation of immutable work. English uses the same orchestrator/compiler and preserves qualitative uncertainty. This is deterministic, evidence-conditioned engineering; it is not a claim of independently intelligent semantic tutoring.

Supported bounded capabilities include source reading/highlighting, progressive accepted operations, responsibility/concept/argument diagrams, directed relationships, checked arithmetic and units, finite inert algorithm traces, registered experiments, checked constant-rate graphs, equivalent tables, annotations, classification/parameter/step operations, checkpoints, undo/redo and committed canvas evaluation. Unsupported algebra and arbitrary executable content reject. General unrestricted teaching composition is unavailable: the compiler admits reviewed fragments and checked capabilities.

**Status distinctions:** code implemented and isolated behavior tested/demonstrated; real academic qualification and independent expert suitability **pending**; genuine provider inference **unverified/unauthorized**; live database installation and production readiness **blocked**. No M6/M7/M8 release claim.

## C. Teaching Action Engine

`teaching-engine.ts` supplies strict bounded review, decision, compiled action and public-state schemas. `petros-teaching-actions.ts` validates an exact reviewed fragment, all source/quotation pins, directed relationships, capability availability, equations and graph/kernel consistency. The compiler preflights every semantic prefix and target before publishing any action. Every equation display is bound to the checked calculation. Checked instruction and the student's actual saved value are distinct fields.

Actions publish atomically through the session command transaction with idempotency, revision and epoch checks. Subsequent steps revalidate current authority. Every accepted operation creates an existing workspace checkpoint and operation receipt. The action is limited to 32 operations; the session has 20 teaching decisions and bounded checkpoint/history limits. A valid schema/citation is not academic validation.

The database additionally requires public teaching metadata to equal the corresponding independently fixture-reviewed instrument payload. Substitution of an unreviewed public explanation fails with `M5_EXACT_REVIEWED_TEACHING_REQUIRED`.

## D. Orchestrator

The context includes current student/session authority, objective/scope and exact sources, committed criterion outcomes, assistance/equivalence conditions, current work, concept mappings, capabilities, accessibility availability, budget/deadline and uncertainty. It excludes private checker values, rubrics and discriminators. Source, review, scope, epoch, accessibility, budget and independent-task restrictions run before selection.

The policy maps reviewed criterion categories to instructional strategies. It never branches on student identity, subject/title, response keywords or objective ordinal. Conceptual errors motivate contrasts; arithmetic/method errors motivate focused repair; ambiguous interpretations ask for clarification/review; assisted success selects faded support; eligible success seeks fresh verification. Conflicting evidence prevents a confident misconception assertion. Explicit student requests can select a reviewed experiment, process or graph capability within scope.

Each decision stores criterion/evidence IDs, candidate hypothesis, uncertainty, strategy, reason, expected observation, alternatives and termination. `m5.decision` events provide the engineering trace. The model cannot assign grades, approve instruments, change evidence, grant access or execute code.

## G. Canvas construction

Stable element IDs, semantic types, source unit IDs, revisions, optional groups, labels/accessible descriptions and edit boundaries are shared between Petros and student work. New structured graph/table/trace elements extend the same reducer. Graph points are checked against the registered linear-rate kernel and have a numeric table alternative. Tables reject ragged rows and permit only declared cell edits. Trace transitions are finite, ordered and inert.

Registered student operations include scoped annotation/add/remove/move/connect/disconnect/content replacement/highlight, bounded parameters, classification, step/cell edits and durable checkpoint/commit/undo/redo commands. Not every operation is enabled in every invitation. Protected source elements and table labels cannot be edited. Parent cycles, dangling/reversed unreviewed teaching relationships, stale versions and conflicting edits reject. Rendering does not admit evidence.

## H. Student work

Each submission pins the exact immutable response, checkpoint, canvas revision and snapshot hash. The evaluator-only work reader returns the immutable checkpoint and response hashes; the evaluator recomputes both before checking canvas values or relationships. Live client correctness fields are never accepted. After commitment, undo cannot erase the submission. The existing tables retain multiple task/response rounds, and progress counts actual history rather than reverting to one response per session.

Assistance, source access, replay, equivalence and unknown outside help remain explicit. Practice correction is assisted. A new independent boundary requires an unused separately reviewed transfer family. Exposures are retained, not deleted. Prose explanations are saved even where this milestone has no qualified qualitative evaluator.

## I. Assessment

M4 exact/numeric checks remain private. Added deterministic canvas-value and directed-relationship checks operate on the committed snapshot. A correct final capacity with an invalid available-memory step cannot satisfy both criteria; a correct method with an arithmetic slip receives focused repair. Free-form reasoning and English interpretation still abstain. No official marks or learning evidence come from model output, animation, prediction completion, confidence or a frontend selection.

The existing private evaluator/database-role separation, criterion manifests, current review/source checks, fence/lease publication, failure states and evidence admission remain intact. Failed evaluation preserves committed work without inventing success.

## J. Concept beliefs

The new projection is owned by the existing learner-evidence service and rebuilt from the existing objective ledger. The cache stores categorical `not_assessed`, `developing`, `demonstrated_in_session`, `retention_supported`, `review_due` states, exact concept/version and graph/algorithm/publication pins, an as-of time, evidence IDs, hypotheses/counterevidence and a projection hash. No percentage mastery score is invented. A criterion is demonstrated only after two eligible independent families; ineligible negative observations cannot promote a hypothesis to supported.

Demonstration requires coverage across distinct independent non-equivalent families, including explanation and application roles. Assisted/equivalent work cannot satisfy those requirements. One suggestive error remains a candidate; distinguishing independent evidence is required to support a hypothesis. Corrections/revocations fold history without rewriting it. Cyclic/missing/future ledger lineage rejects. A later real retention observation would be required; the repository currently admits no retention checks and this run claims none. Test clocks establish policy behavior only.

## O. Security

The M5 runtime exposes no shell, filesystem, network discovery, arbitrary patch, arbitrary solver or executable code. Tools have closed inputs/outputs, current authority, source/capability requirements, payload/runtime limits, public-only redaction and reject/abstain failure behavior. The gateway seam uses the existing `teaching.next_action.select` function, a durable budget/fence, short DB scopes, pre/post authorization, strict structured output, bounded tokens/deadline and zero retry fan-out. Controlled responses are labelled controlled; live origin requires an actual provider receipt. Normal sessions do not enable that seam without separate provider qualification.

Tests reject lost source/review/scope/epoch, fabricated pins/quotes, unreviewed compositions/relationships, invalid graph endpoints/values, unsupported equations/units/division, missing alternatives, oversized actions, protected edits, arbitrary executable fields and model grade/approval/evidence writes. Cross-student session reads and belief writes, normal-app access to the evaluator snapshot function and public teaching substitutions are denied. The [50-category adversarial coverage map](m5-20261019T052910Z/adversarial-coverage.md) identifies the specific tests and limits.
