# Classic learning: novice usability protocol

25 October 2026. **Preparation only; no participants tested and no human results
claimed.** Use the actual redesigned application after the approved prototype has
been inspected and implementation/engineering checks have completed.

Recruit genuine first-time students. Explain that the interface is being tested,
not the student. Obtain appropriate participation/recording permission and use
authorized disposable or approved test accounts. Record device, viewport, input
method, assistive technology and reduced-motion preference. Do not record private
student answers or credentials in shared evidence.

Give one task at a time without telling the participant where controls are.
Record completion, time, confusion, mistaken action, help required and the
participant's own explanation. Do not turn observer hints into independent success.

| Task | What to observe |
| --- | --- |
| 1. Identify available memory | Can the student distinguish total, reserved and memory available to VMs? |
| 2. Make a prediction | Is the actual authorized answer format clear? Can they tell when it is saved? |
| 3. Run the VM experiment | Can they add VMs using touch/keyboard without needing drag-and-drop? |
| 4. Recognize the refusal | Do they understand the extra VM was refused and existing allocations remain? |
| 5. Explain the limit | Can they find and use the explanation field without the companion covering it? |
| 6. Save an explanation | Can they distinguish an acknowledged save, unsaved draft and failed save? |
| 7. Ask Petros for a hint | Is help discoverable, policy-appropriate, readable and clearly unavailable when restricted? |
| 8. Dismiss a cloud | Can they close it by keyboard/touch and continue where they were working? |
| 9. Find earlier experiment details | Is More options recognizable and is history clearly separate from the current attempt? |
| 10. Distinguish saving and checking | Can they explain Saved · Not checked yet, evaluation pending, assisted correction and teacher review? |

Include an honest prediction error, a refused allocation, a retryable network save
failure and a real review/unavailable evaluation. Do not fabricate results to make
the interface look successful. Ask whether Petros helped or distracted, whether the
cloud was associated with him, and whether the next action was obvious.

Repeat appropriate tasks at 360px and 390px, on a real touch device, by keyboard,
with reduced motion and with a screen reader/enlarged text. Engineering emulation
does not replace those observations. Keep Classic usable if the character is
hidden or text-only mode is selected.

Outcome record: **Pending recruitment and human testing of the implemented application.** Leave
participant counts, completion rates and usability conclusions empty until observed.
